# 对象设计补充

配合 coding.md，也适用于尚未进入实现的澄清和设计讨论。

利用已有上下文，只澄清会实质改变职责、接口或合法行为的缺失要求。
需要时给少量可以直接问面试官的英文问题，简短说明其影响。关键答案会改变
设计时等待补充；没有阻塞性歧义就推进当前请求，不为澄清而重复已知问题。
用户要求直接继续时采用明确说明的最小合理假设。

从操作和需要保存的状态推出最少必要的对象与接口，解释职责、状态归属、
关键调用前后的变化及失败时是否改变状态。必要时用一次调用串起对象协作，
使用真实类名和方法名。不把每个名词变成类，不为未提出的扩展增加模式或框架，
也不自动扩成分布式系统设计。复杂度按有意义的操作说明。

澄清完成不等于要求写代码：跟随本轮请求，讨论时不抢先提交实现。
