# 面试助手：当前产品

左侧持续回答，右侧按需打开题目工作区。桌面和横屏手机使用同一界面。

## 面试中怎么用

1. 普通简历、BQ、计算机基础问题正常听、正常回答，无需打开工作区。候选人转写只在后台补充上下文。
2. 进入代码题后，可以直接按“分析这题”。有屏幕材料则先截图；多个文件、长题目可连续截几张，再一起分析。纯口述不需要截图。
3. 工作区“分析”保存当前题意、关键观察、方案和待澄清事项；“代码”展示模型一次组织出的完整步骤。尚未适合编码时只提供分析。
4. 上下步箭头只翻页；文件 tabs 标出“本步”涉及的文件。建议用 diff 展示，实际代码按需展开，用户在外部编辑器写代码。
5. 自己改了变量、只写了一半或需求改变后，再截图并按“更新方案”。模型从实际代码重新规划剩余步骤。翻页不代表写完，也不会把建议应用成实际代码。
6. “换题”归档旧题工作区并清空待用截图；文字回答仍按整场面试连续保留。结束面试按钮始终可见。

截图、分析/更新、换题是常用操作；更多中只有补充信息、暂停/继续回答、主题和有截图时的清空操作。没有题型选择器、自动阶段流程或用户维护的上下文表。

## 实现边界

- 复用 Live 与托管 Astra、已有三个工具及一条 client WebSocket。
- files 保存实际代码；现有 proposal 保存 analysis、steps、base_files。不增加另一套工作区或答案存储。
- 每一步基于前一步假设结果，版本检查始终针对实际文件；整个方案验证后一次发布。局部截图保留未知，不能补造整文件。
- 普通新语音、截图不取消任务；显式停止、换题、暂停和用户修改保留原有失效保护。
- session_ready.code_plan=true 声明新能力；旧后端禁用新控制。重连恢复限于同一服务进程，服务重启仍不恢复本场。
- 候选人使用流式转写；WebRTC VAD 只给转写记录收尾，不裁剪原始音频、不触发回答。面试官的接话和委派仍由 Live 决定。
- 不故意制造错误，不把候选人未说过的内容当事实，不声称执行过未执行的测试。

架构细节见 [architecture.md](architecture.md)。本地使用在 apps/desktop 运行 `npm.cmd run start:local`，它启动真实 Electron 和本地后端；浏览器只作同场界面，采集仍由 Electron 承担。
