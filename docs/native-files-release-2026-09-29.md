## 产品现在的行为

1. 删除「更新代码区」按钮。输入框发送文字；空输入时同一个按钮是「回答」，使用现有上下文；生成中是停止。
2. 聊天始终是解释、澄清和讨论的入口。当前请求需要实现时，Codex 用原生工具写代码文件；小段示例和解释无需修改右侧。
3. 每个会话使用 `assistant-workspace/conversations/<会话 ID>/`。同题修改原文件；新题实现另建文件；旧文件保留。Git 留版本，右侧同步真实文件，没有额外的 update_code 发布工具。
4. 文件在一轮结束或中断得到确认后同步。改动有 diff，新文件完整显示；中断留下的修改标为未完成。无改动的讨论不创建新 Git 版本。历史仅浏览，不影响当前文件。
5. 截图仍手动附在消息上，只发送所选附件。截图供模型理解，不自动维护外部编辑器镜像；首次文件生成不伪造全绿 diff，旧截图比较档案仍可浏览。
6. 转录完整记录在应用中。首轮带现有记录，以后只带新增或修正的 turn；相同 turn_id 的修正覆盖旧文字。生成过程中到达的语音留到下次请求，不自动回答、不打断当前生成。
7. 主提示词是 `assistant-workspace/AGENTS.md`，通过原生 baseInstructions 进入 Codex；简短 coding / algorithms / object-design 指南按需读。没有题型分类模型或阶段状态机。
8. 原生读取文件、搜索、执行命令等状态可折叠查看；不展示内部推理、原始命令参数和命令输出。
9. 完整代码不逐轮重新塞入消息；需要时 Codex 读取当前文件。旧固定代码首次迁入，不覆盖新文件。SQLite 保留显示记录，文件/Git 是代码来源。

## 真实模型场景与观察

- 简历介绍、错误指标纠正、CourseHub 社区规模与 DAU 区别、Reachard 技术挑战、缺失的冲突故事。
- 口述 log parser：字段解析、AND/OR、顺序、大小写、非法行；随后新增 limit 并保持原有逻辑。
- OOD：停车场、售货机和图书馆范围澄清；确认需求后实现停车场/内存文件系统。
- 手动截图中的链表加法；剩余 carry 追问；新题保留旧文件。
- 正则 DP、状态转移追问；递归 formatter、转义、缺失 key、循环引用。
- 最多破一堵墙 BFS；为什么 visited 需要区分是否破墙。
- 转录纠正后回到早前函数，技术题与个人问题在同一 thread 切换。

所有只讨论、澄清或检查的回放轮次均未产生文件改动；实现轮次创建/修改了相应文件。缺失 BQ 故事没有被补成虚构事实。

早期回放发现 Windows 默认配置下写文件仍失败，已显式配置原生 unelevated workspace-write；重测确认可写且每会话有独立 Git。也发现默认编程代理风格导致操作前言、完成摘要和英文注释，改用面试主指令后，后续回放直接解释算法/对象状态，关键注释为中文。

## 明确限制

- **这不是 Sol 质量/速度验收。**真实模型用获准的独立 Luna；24 轮完整耗时约 3.1–81.7 秒，首文字约 1.6–55.2 秒。不能用较快的状态或前言冒充更早的有效答案。生产模型未降档，复杂回答仍可能等待几十秒。
- 部分示例的复杂度解释仍偏简略：文件系统按路径段计量时应考虑字符串成本，formatter 的 active 列表查找不能无条件算 O(1)。已补充通用核算提醒，但这些样本不能证明模型后续不会再漏算。
- 测试参考了可读取的 Kikoff HR/解析题方向、Whatnot 讨论及用户给出的模拟材料；**未能取得全部原始面经题面，不能称为所有公司原题逐题通过**。破墙 BFS 明确是模拟题。
- 一轮额外的真实简历/BQ复测被自动审批拒绝，原因是要求更明确的私人资料外发授权；没有重试该动作。最终补测改为仅含虚构档案与公开指南的独立目录，未复制真实材料。
- 文件区复杂度不再由应用猜测：复杂度在普通回答中解释，旧档案仍可显示已有复杂度。新文件的 diff 以真实 Git 上一版为准，截图识别仍可能出错。
- 同步时点是本轮结束/确认中断，不承诺逐字符文件镜像。停止不会撤销已经写下的文件；Git 版本不是代码正确性证明。
- CLI 登录、线程历史与真实代码在电脑；手机仍需这台 Electron 在线。未测试真实麦克风识别准确率。
