# Cue 0.4.2 — current reads and client-owned transcription

Implemented the approved `2026-10-19-read-and-transcription-target.md` contract. Protocol is `cue-chat-v3`; Mac build is 36. This is a coordinated cloud, Mac and Windows release.

## Behavior

- MCP checkpoints store immutable baseline/seen state, never response pages. Every call queries current data. Reusing an old cursor can repeat content but cannot replay a frozen old question. One cursor supports live updates and explicit `older` history, with `more.new` / `more.older`. Invalid, expired and v2 checkpoints reset visibly. Metadata is supplied both as structured content and text within the existing wire budget.
- The shared desktop client owns OpenAI connections, commit pairing, sentence revisions, cutoff ordinals, retries and 55-minute upstream handover. Cloud only issues credentials and acknowledges idempotent sentence writes. Late older revisions cannot replace a final transcript. Additive migration `0009_utterance_ordinal.sql` retains existing records.
- Answer boundaries freeze PCM before waiting for a previous commit. Post-click PCM follows the cutoff commit; cloud excludes later ordinals even if those sentences save first. A rejected commit cannot silently count as a successful cutoff.
- Recording stops locally before tail processing finishes. Tail failures identify their stage; unsaved snapshots stay in memory and retry after recovery. Audio never automatically restarts. No periodic Sites connection replacement was added.
- The Windows answer-boundary queue retains the full worklet tail during its bounded flush. Native page readiness replays connection state if the WebView loaded after `session_ready`. Caption following uses a layout effect so successive updates do not mistake an intermediate programmatic scroll for user scrolling.
- Screenshot capture, dimensions, burst queue, upload and server-confirmed readiness are unchanged.
