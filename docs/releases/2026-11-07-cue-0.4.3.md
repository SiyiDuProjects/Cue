# Cue 0.4.3：删除聊天残留

## 改动

聊天切换在 10 月已从界面删除，但协议里还留着骨架：握手返回聊天列表，客户端选最新一个，没有就发 `new_chat`，每次 ask 和 history 都带聊天标识，云端再核对该聊天存在。三端为此各维护一份聊天状态，实际只用来填一个从不显示的字段。

- 协议升为 `cue-chat-v4`。ask、history 不再带 `chat`；云端删除 `new_chat`、`chat_created`，握手和 `state` 不再返回聊天列表。
- 新回答写入旧 `chat` 列的固定值 `timeline`，R2 输出存于 `chat/timeline/`。`chats` 表和旧回答不删，旧回答仍按时间参与最近一小时回放。没有数据库迁移。
- Windows 与网页共用的悬浮条、Mac 原生模型和预览、连接检查、付费长测驱动同步删除聊天逻辑。Electron 请求白名单去掉已不存在的 `/capture/materials`。
- 私有云端 README 中过时的 0.4.1 协议和 MCP 读取描述已按现行 cursor 行为改正。

截图、转录、cursor、遥控、回答截止与回放规则均未改动。

## 验证

- 云端：49 项测试通过，Worker 构建与产物检查通过。新增断言：新回答写入 `timeline`，旧聊天行的回答仍被回放，`new_chat` 与 `rename_chat` 被拒绝。
- 跨端上下文回归：10 项通过。
- 桌面：45 项检查，44 通过，1 项既有平台跳过。Windows、Mac 回答页与网页构建通过。打包 UI 测试三项通过，并断言 ask 不带聊天、不发聊天指令。
- 网页设置与遥控真实 DOM 测试通过，外网阻断。
- Mac：CueChecks 与 114 项原生音频投递检查通过。付费长测驱动只做类型检查，未运行。
