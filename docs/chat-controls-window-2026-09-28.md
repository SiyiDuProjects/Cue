# 按钮、回答和桌面窗口整理

针对用户 0.1.5 截图中的按钮层级、简短回答及无标题栏问题。

## 改动

- 主操作仍为截图、回答、更新代码区、发送/停止。截图准备附件；回答使用当前上下文；更新代码区明确允许工具发布固定代码；发送使用输入框。避免将不同副作用合成一个含糊按钮。
- 普通聊天/模拟面试的常驻按钮删除。更多中提供切换模拟面试/切回普通聊天；转录进行中禁用切换。选择模式本身不启动音频或模型。
- 代码历史的同一对话框查看本场版本和往场代码，删除更多里的重复入口。浏览往场后仍能查看该往场的版本，回到当前代码不修改代码内容。
- 打开/收起工作区改称代码区。
- 回答指令要求与问题匹配的解释深度。新解法讲清思路、理由、边界，示例按需；简单追问不强套完整报告。只固定已经解释过的代码仍可简短确认。避免“我会……”等无用前言；不在前端过滤原文。
- 桌面恢复系统标题栏，支持最小化/最大化/自由缩放，默认不置顶，系统管理边框、阴影和圆角。删除已无入口的悬浮窗折叠/置顶控制、IPC 和相关 React 状态；代码区开关不改变原生窗口尺寸。
- 关闭窗口沿用托盘保活，避免中断浏览器采集；托盘退出才完全退出。

## 为什么回答短

截图是“更新右侧代码区”的请求，前文已存在解法；这种请求返回确认本身合理。当前提示词和托管调用没有限制为几句话，UI 也不截短正文。原指令没有充分表达首次讲解应交付多少理由，所以补充回答质量规则，不改变模型和 high 推理配置，也不设置强制字数。

托管 Agent 的配置在新建会话时创建，因此新提示词要在更新服务后开启新对话才生效。本轮没有真实模型调用，不能用离线检查证明自然语言质量已经改善。
