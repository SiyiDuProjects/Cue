# Sage 聊天改造验收 · 2026-09-28

本次按用户的新方向替换正式辅助模式：双路语音只转录，显式消息通过 Responses 生成文字并调用代码工具。没有部署或启动真实面试。

后续用户澄清：代码区不自动附加到每条消息。现已改为截图确定外部实际代码，后台按需读取维护的代码区；下文“自动携带当前工作区”记录的是首版实现，已被此澄清替代。

## 可见变化

1. 使用现有 CollectUI / HeroUI Pro 的 ChatMessage、ChatAttachment、PromptInput 构建聊天区。用户消息和助手回答逐条排列，分析/OOD/澄清属于普通 Markdown 回答。
2. 删除独立分析面板。主入口是输入框、截图、回答、写代码；生成中提供停止。换解法、解释、优化等可直接输入，不再分别增加主按钮。
3. 手动截图成为待发送附件，可预览、移除；接受消息后移到对应气泡。发送期间新截的图留待下次。历史附件支持重连恢复和后续追问。
4. 代码区独立显示 diff、复制、复杂度和同题历史。小实现可只有一步；多步才显示步骤导航。步骤修改/拆分保留在次级菜单，第一步直接是代码修改。
5. 换题只归档代码工作区、清空待发附件，保留聊天。停止保留已生成的回答、已发布代码和正在输入的下一条草稿。

## 后台变化

- 正式辅助不再创建 GPT-Live 会话或托管后台。系统音频与麦克风各用独立 Realtime transcription；说话本身不触发回答。原有可选模拟面试官仍独立保留。
- `responses_chat.py` 是唯一回答入口，继续用配置中的 Sol/high，通过 HTTP SSE 流式输出。没有语音字幕转述、伪造打字速度、隐藏模型片段或自动难度路由。
- 每条请求自动携带本场完整背景、按时间排列的转录与聊天/已发送图、当前工作区。ASR final 更新同一段，不重复累积 delta；不引入摘要模型、碎片检索或静默裁剪。容量不足会明确报错。
- 同一请求处理三个工具：`search_context`、`capture_current_screen`、`update_code`。工具 schema 已去掉 analysis；代码工具仍区分实际观察与未实施建议，保留原子发布、文件版本、局部截图保护。
- 工具循环保留完整 Responses output items 与加密 reasoning。只在 response.completed 后执行完整工具，截断参数不执行。模型按用户请求补取的截图也附到该条消息。
- 一场只运行一条显式生成；第二客户端冲突明确拒绝，不消耗其附件。停止、换题、结束会使旧写入失效；新转录不取消当前请求，也不声称当前生成已吸收后来信息。
- 删除旧辅助 Live 调度、候选人转录转发、屏幕跟随和旧快捷回答/隐藏片段规则。步骤菜单请求会显示具体目标标题，避免聊天里只留下没有指代的“修改此步”。
- 更新 AGENTS、README、architecture、部署探针及协议 `interview-chat-v6`。旧架构讨论文档已标为历史；旧 v5 不能与新客户端混用。

## 尚未验证的边界

- 未调用真实模型，也未做麦克风/系统音频端到端验收；不能把合成测试称为 Sol 回答质量或延迟验证。
- 默认模型与推理档位未换；移除语音表达与委派路径，不等于承诺模型推理本身更快。
- 全文上下文仍受模型容量和图像输入费用约束；保留所有已发送图便于追问，并不保证任意长度会话都能装下。
- 当前会话仍是服务端内存态：普通断网可恢复，服务重启不能恢复整场聊天；工作区档案另有持久保存。
- 未部署生产、未发布安装包。上线必须先发布并核对 v6 后端，再分发匹配客户端。
